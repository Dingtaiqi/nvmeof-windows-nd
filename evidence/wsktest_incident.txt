WHAT WENT WRONG
  sc stop nvmeofwsk -> first attempt exit 1052 (ERROR_INVALID_SERVICE_CONTROL,
  "The requested control is not valid for this service"); the service had
  reported (STOPPABLE) right after start and (NOT_STOPPABLE) at that point.
  A later stop attempt was accepted and never returned; after that `sc query`
  blocks and a fresh powershell.exe running only Write-Output "alive" does not
  complete.  The machine is partially wedged (no bugcheck, no dump, no reboot).

  The only driver code on that path is DriverUnload, which performs two registry
  writes (wsktest_log, wsktest_unload).  Registry I/O from DriverUnload is the
  prime suspect.  nvmeof_tcpk.c's NvtcpkUnload and nvmeofk.c's unload routine
  also do registry I/O (NvtcpkLogFlush), so this is a real defect to chase.

  Evidence that it is process creation, not just the tool: a fresh
  powershell.exe whose FIRST statement was
      Set-Content D:\rdma\wsktest_heartbeat.txt ...
  never created that file within 30 s, and a glob (which spawns a helper) timed
  out too, while in-process file reads/writes still worked.  So new processes
  cannot complete startup; nothing was bugchecked (this session survived, so the
  machine never rebooted) and no new dump appeared.

  Load #2 was NOT attempted: the brief requires a clean unload first, and the
  machine stopped being able to run diagnostics.  Two loads are budgeted; one
  was used.
